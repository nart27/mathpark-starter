# Математический парк — учебный каркас

Учебная копия структуры [museum.adygmath.ru](https://museum.adygmath.ru/ru/) для практики РЕМШ. Это самостоятельная реализация, а не точный клон кода исходного сайта.

## Быстрый запуск

Распакуйте весь архив и откройте `index.html` в Edge или Chrome. Сервер, Node.js и Python для просмотра не нужны. Фотографии находятся внутри проекта.

**Пошаговая инструкция:** откройте [START_HERE.html](START_HERE.html) в браузере или прочитайте [WINDOWS.md](WINDOWS.md).

**Распределение моделей:** [кто готовит какие страницы](docs/ASSIGNMENTS.md).

## Что готово

- Главная: 11 моделей, фильтр заполненных страниц и заглушек.
- Страница «О парке».
- Заполненные страницы: теорема Пифагора, лист Мёбиуса, параболические шепталки.
- Отдельные страницы-заглушки для остальных восьми моделей.
- Общая адаптивная стилизация, меню, увеличение фотографий, источники.

## Файлы

```text
mathpark-starter/
  index.html                 Главная и карточки моделей
  about.html                 О парке
  models/                    11 отдельных HTML-страниц
  assets/css/styles.css      Общие стили
  assets/js/main.js           Фильтр и просмотр фотографий
  assets/images/             Местные фотографии
  WINDOWS.md                 Инструкция для студентов
  TASKS.md                    Работа на два дня
  ASSET_SOURCES.md            Источники материалов
  docs/                      План и журнал решений
```

Редактировать можно обычные HTML-файлы. Контент не подгружается через `fetch`, поэтому локальный запуск через двойной щелчок работает.

## Как заполнить заглушку

1. Откройте первый из двух своих файлов в models/ по таблице docs/ASSIGNMENTS.md.
2. Откройте соответствующую страницу оригинала по ссылке на странице.
3. Изучите любой из трёх заполненных примеров.
4. Замените блок `.placeholder-notice` и список «Что добавить» своими секциями.
5. Сохраните локальные изображения в `assets/images/`; из модели путь начинается с `../assets/images/`.
6. На главной измените у карточки `data-status="draft"` на `ready`, подпись и статус; обновите счётчики.
7. Проверьте страницу, меню, фотографии и узкий экран.

## Источники и границы копии

Каталог, фотографии и проверяемые сведения взяты с исходного сайта; ссылки приведены в [ASSET_SOURCES.md](ASSET_SOURCES.md). Пояснения пересказаны для учебных страниц; вопросы и опыты добавлены в каркас.

В каркасе только русская версия. Формы, аналитика, служебные скрипты и отправка сообщений исходного сайта не скопированы. Все изображения хранятся локально.

## Как отправить правки в общий проект

Общий проект: [nart27/mathpark-starter](https://github.com/nart27/mathpark-starter). Для совместной работы используйте инструкцию ниже; упоминания общего GitLab в старых учебных материалах больше не актуальны. Понадобятся аккаунт GitHub, GitHub Desktop и редактор, например VS Code. Командная строка не нужна.

**Схема работы:** fork (ваша копия общего проекта) → ветка → правки → commit → push → pull request → проверка руководителем → объединение с `main`.

### 1. Создайте свою копию — один раз

1. Войдите на GitHub и откройте [общий репозиторий](https://github.com/nart27/mathpark-starter).
2. Нажмите **Fork** → выберите свой аккаунт → **Create fork**. Получится `ВАШ_ЛОГИН/mathpark-starter`, связанный с общим проектом. Доступ на запись в общий репозиторий не требуется.
3. Если такой fork уже есть, откройте его. Обычный личный репозиторий из первого упражнения не является fork: готовые файлы из него перенесём на шаге 3.
4. В GitHub Desktop войдите в тот же аккаунт. Выберите **File → Clone repository → URL**, вставьте адрес своего fork и клонируйте в отдельную папку, например `Documents/mathpark-team`. Не используйте папку первого упражнения.

### 2. Обновите копию и создайте ветку — перед каждой новой задачей

1. На GitHub откройте **свой fork**, выберите `main` и нажмите **Sync fork → Update branch**, если есть новые изменения. Если GitHub сообщает о конфликте, отправьте ссылку руководителю.
2. В GitHub Desktop выберите эту копию в **Current repository**, затем `main` в **Current branch**. Нажмите **Fetch origin**, затем **Pull origin**, если кнопка появилась.
3. Выберите **Current branch → New branch**. Назовите ветку латиницей по задаче, например `varvara/dodecahedron`, и нажмите **Create branch**. Проверьте, что в **Current branch** указана новая ветка.

### 3. Внесите и проверьте правки

1. Откройте папку `mathpark-team` в VS Code. Найдите свои страницы по [распределению моделей](docs/ASSIGNMENTS.md).
2. Отредактируйте свои HTML-файлы. Если работа уже готова в личном проекте, скопируйте только изменённые страницы и нужные изображения с сохранением путей. Не заменяйте весь проект старой копией.
3. Фотографии добавляйте в `assets/images/` с понятными уникальными именами. На главной меняйте только свои карточки; общие стили, JavaScript и итоговые счётчики согласуйте с руководителем.
4. Сохраните файлы. Откройте `index.html` из этой папки в браузере: проверьте переходы на свои страницы, меню, фотографии и вид при узком окне.

### 4. Сохраните изменения и отправьте их на GitHub

1. В GitHub Desktop откройте **Changes**. Просмотрите список файлов и изменения в каждом из них; оставьте отмеченными только файлы своей задачи.
2. В **Summary** напишите, что сделано, например `Добавлено описание додекаэдра и фото`. Нажмите **Commit to …** с именем своей ветки.
3. Нажмите **Publish branch** при первой отправке ветки; для следующих commit — **Push origin**.
4. Откройте свой fork на GitHub и переключитесь на эту ветку. Убедитесь, что файлы и последний commit появились.

**Commit** сохраняет историю на компьютере, **push** отправляет её в ваш fork. В общий проект правки попадут после принятия pull request.

### 5. Создайте pull request в общий проект

1. На GitHub в своём fork нажмите **Compare & pull request**. Если кнопки нет, откройте **Pull requests → New pull request**; при необходимости выберите **compare across forks**.
2. Проверьте направление: **base repository** — `nart27/mathpark-starter`, **base** — `main`; **head repository** — ваш fork, **compare** — ваша рабочая ветка.
3. Откройте **Files changed** и убедитесь, что предлагаете только свои правки.
4. Укажите понятный заголовок, например `Додекаэдр: описание, опыт и фотографии`. В описании перечислите изменённые страницы, что добавлено и как проверено; отметьте, если работа ещё не закончена.
5. Нажмите **Create pull request**. Для незавершённой работы выберите **Create draft pull request** в меню этой кнопки.
6. Отправьте руководителю ссылку на pull request. Он проверит работу и объединит её с `main`. Создание pull request само по себе не обновляет общий сайт.

### 6. Исправьте замечания и начните следующую задачу

1. Если пришли замечания, откройте ту же ветку в GitHub Desktop, исправьте файлы, сделайте новый commit и **Push origin**. Открытый pull request обновится автоматически; второй создавать не нужно.
2. Если появился конфликт, сообщите руководителю, какие файлы затронуты. Согласуйте объединение, чтобы сохранить правки одноклассников.
3. После статуса **Merged** повторите шаг 2: обновите `main` своего fork и локальной копии, затем создайте новую ветку для следующей задачи.

**Что сдавать:** ссылка на pull request в `nart27/mathpark-starter`, перечень своих страниц и краткое описание проверки.

Справка GitHub: [клонирование и fork в Desktop](https://docs.github.com/en/desktop/adding-and-cloning-repositories/cloning-and-forking-repositories-from-github-desktop), [создание pull request](https://docs.github.com/en/desktop/working-with-your-remote-repository-on-github-or-github-enterprise/creating-an-issue-or-pull-request-from-github-desktop).
